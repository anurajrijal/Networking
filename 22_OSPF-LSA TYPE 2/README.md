# OSPF Multi-Access Network — DR/BDR Election & Type 2 LSA

## Topology

```
                Shared Ethernet Segment (Area 0)
        ┌──────────────┬──────────────┬──────────────┐
        │               │              │
      R1 (Gi0/0)     R2 (Gi0/0)     R3 (Gi0/0)
   Priority 100    Priority 200   Priority 100
```

All three routers connect to the **same Layer 2 broadcast segment** (e.g. via a switch), all in **OSPF Area 0**.

> Replace the IP addressing below with whatever your lab actually uses — the addressing here (`192.168.1.0/24`) is a placeholder based on a typical 3-router single-segment design. Update Router IDs and interface names (`Gi0/0`, etc.) to match your topology.

| Router | Interface | IP Address | OSPF Priority | Expected Role |
|---|---|---|---|---|
| R1 | Gi0/0 | 192.168.1.1/24 | 100 | BDR or DROTHER |
| R2 | Gi0/0 | 192.168.1.2/24 | 200 | **DR** |
| R3 | Gi0/0 | 192.168.1.3/24 | 100 | BDR or DROTHER |

## R1 Configuration

```
enable
configure terminal

hostname R1

interface gigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 ip ospf priority 100
 no shutdown
exit

router ospf 1
 router-id 1.1.1.1
 network 192.168.1.0 0.0.0.255 area 0
exit

end
write memory
```

## Verification Commands

### 1. Confirm OSPF neighbors formed correctly

```
show ip ospf neighbor
```
Expect to see the other two routers listed, with one showing state `FULL/DR`, one `FULL/BDR`, and (if a third distinct role exists) `FULL/DROTHER`.

### 2. Confirm DR/BDR election result

```
show ip ospf interface gigabitEthernet0/0
```
Look for the lines:
```
Designated Router (ID) ...
Backup Designated Router (ID) ...
```
This confirms which Router ID won DR and which won BDR on that segment.

### 3. Inspect the OSPF Link-State Database for the Type 2 (Network) LSA

```
show ip ospf database
```
Look for a **Net Link States** section — this is where Type 2 Network LSAs appear. They are only generated by the **DR** on broadcast multi-access segments.

For more detail on the Type 2 LSA itself:
```
show ip ospf database network
```

### 4. Confirm routes learned via OSPF

```
show ip route ospf
```

## Key Concepts Demonstrated

- **DR/BDR election** exists only on broadcast (and NBMA) multi-access network types — not on point-to-point links, where OSPF skips election entirely and both routers become full neighbors directly.
- **Priority** is the primary tiebreaker for DR/BDR election (higher wins); if priorities are equal, the highest **Router ID** wins instead.
- Setting a priority of **0** on an interface excludes that router from DR/BDR election entirely (it can only become DROTHER) — useful to know even though this lab uses 100/200 to force a clear winner.
- **Type 2 Network LSAs** are originated by the DR to represent the multi-access segment itself and list all routers attached to it. They don't exist on point-to-point links because there's no DR/BDR concept there — LSAs are exchanged directly between the two neighbors instead.
- If DR/BDR roles need to be re-triggered after a priority change, remember that OSPF **does not re-elect DR/BDR automatically** just from a priority change — the interface (or router) typically needs to bounce (`shutdown` / `no shutdown`) or OSPF needs to be cleared (`clear ip ospf process`) for the election to re-run.
